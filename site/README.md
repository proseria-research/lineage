# Lineage website & guides

The public site for Lineage: a custom landing page plus the user-facing guides, built with
Astro and Starlight and deployed to Cloudflare as static assets.

This is **not** the design documentation. `docs/` at the repository root holds the internal
numbered design documents and stays internal. Nothing here is generated from them.

## Commands

From the repository root:

| Command | Does |
| --- | --- |
| `make site` | Install and build into `site/dist` |
| `make site-dev` | Dev server on `localhost:4321`, hot reload |
| `make site-preview` | Build, then serve it — what Cloudflare actually serves |
| `make site-check` | Type-check the Astro components |
| `make site-links` | Fail if any internal link 404s |
| `make site-deploy` | Build and `wrangler deploy` |

Or from `site/` directly:

| Command | Does |
| --- | --- |
| `pnpm install` | Install dependencies |
| `pnpm dev` | Dev server |
| `pnpm build` | Static build into `./dist` |
| `pnpm preview` | Serve the build |
| `pnpm check` | Type-check |
| `pnpm cf:preview` | Build and serve through the Workers runtime (`wrangler dev`) |
| `pnpm deploy` | Build and deploy |

Search is empty under `site-dev` — Pagefind only indexes at build time, so use
`make site-preview` to exercise it.

## Layout

```
src/
  pages/index.astro       the landing page
  layouts/Marketing.astro shell for non-docs pages
  components/             SiteHeader, SiteFooter, Mark, ReleaseDemo, Fingerprint, LineageMap
  components/diagrams/    the guides' SVG diagrams, drawn in the console's style
  lib/demo.ts             the example model the landing page draws
  styles/
    tokens.css            design tokens + the Starlight theme mapping
    landing.css           landing page only
    docs.css              Starlight adjustments
  content/docs/           the guides
    start/                introduction, quickstart, data model
    api/                  publishing, promotion, resolve, lineage, conventions
    governance/           compliance records, audit and retention
    operate/              configuration, deploy, storage, observability and security
    clients/              Python SDK and CLI
```

## Adding a guide

Drop a Markdown file into the right directory under `src/content/docs/` with frontmatter:

```yaml
---
title: Rotating storage credentials
description: One sentence — it becomes the meta description and the search snippet.
sidebar:
  order: 8
---
```

Sidebar groups are autogenerated per directory, ordered by `sidebar.order`.

Guides are technical references: short, verified against the code, tables and examples over
prose. Say what things do; avoid lists of what they are not.

Diagrams are SVG components in `src/components/diagrams/`, wrapped in `Diagram.astro` and
styled by `docs.css`, so they match the console in both themes. A page that uses one is `.mdx`
and imports it. The public site does not use Mermaid; the internal design docs in `docs/` still
do.

## Design

The site uses the admin console's design system, so the site and the product read as one
thing: slate paper, white cards with 8–12px corners, the deep-blue brand `#2b4c7e`, and
status colours (ok, warn, danger) that only ever carry meaning. Type is IBM Plex Sans, with
Plex Mono for identifiers and code, self-hosted through Fontsource. Icons are Lucide, as in
the console.

Copy is plain language, as in the console: say what a thing does for the reader, keep the
official term beside the explanation, and never imply Lineage makes legal decisions.

The landing page's centrepiece is the model card: promoting the staging candidate moves it
into production and archives the incumbent in the same step, which is what the API does in
one transaction, and the resolve line underneath changes with it. The fingerprint drawing
(`components/Fingerprint.astro`) is a port of the console's, seeded from the same hashes as
the example versions in `lib/demo.ts`.

## Deploying to Cloudflare

The build is fully static — no adapter, no server runtime. `wrangler.jsonc` declares a
static-assets-only Worker serving `./dist`.

```bash
pnpm deploy
```

Or connect the repository to Cloudflare Workers Builds with:

- **Root directory:** `site`
- **Build command:** `pnpm build`
- **Output directory:** `dist`

## Before the first production deploy

- Set `site` in `astro.config.mjs` to the real domain. It drives canonical URLs, Open Graph
  tags, and the sitemap.
- Confirm the GitHub links point at the right repository.
